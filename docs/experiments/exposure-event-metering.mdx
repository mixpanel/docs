<Note>
  This page is for projects that send `$experiment_started` events from a third-party experimentation platform or an in-house feature flagging system, and that do not run experiments through Mixpanel Experiments or Mixpanel Feature Flags.

  If you run experiments in Mixpanel, no action is needed — see [Experiments](/docs/experiments).
</Note>

## Why your exposure events count toward MEU

Experiments usage is measured in **Monthly Exposed Users (MEU)**: the distinct users who tracked an exposure event during a calendar month. See [Pricing Unit](/docs/experiments#pricing-unit) for how MEU is calculated and [Plan Availability](/docs/experiments#plan-availability) for the amount included with your plan.

Mixpanel meters the event configured as your project's **exposure event**, whichever system emits it — Mixpanel Feature Flags, a third-party platform, or your own code. Every project starts with that setting pointed at the reserved event name `$experiment_started`.

That means if your project was already sending `$experiment_started` events — for example because you follow the [documented format](/docs/experiments#implementation-for-experimentation) for analyzing third-party experiments in Mixpanel — those events count toward your MEU allowance even though you are not using Mixpanel to run the experiments.

If you don't want those events metered, you have two options. **Option 1 is preferred**: it's a settings change and requires no code deploy.

## Option 1 — Change your exposure event in project settings

Point your project's exposure event setting at an event your project never sends. Your `$experiment_started` events keep arriving and stay fully queryable as ordinary events; they simply stop being counted as MEU.

<Note>
  This option is available on **Growth** and **Enterprise** plans. On a **Free** plan the exposure event is fixed to `$experiment_started` and cannot be changed — use [Option 2](#option-2--change-your-tracking-implementation) instead.
</Note>

<Steps>
  <Step title="Open your Experimentation settings">
    Go to **Settings → Project → Experimentation**.
  </Step>
  <Step title="Change the exposure event">
    Change the event from `$experiment_started` to an event name your project does not send — a placeholder such as `not a real event` works well. The important thing is that no event with that name is ever ingested.

    <Frame>
      ![Experimentation settings](/images/exp_settings_rescale.png)
    </Frame>
  </Step>
  <Step title="Save">
    Save the setting. Metering applies to events ingested from this point forward.
  </Step>
</Steps>

<Warning>
  Once you change this setting, your `$experiment_started` events no longer populate the [Experiment report](/docs/experiments). If you currently analyze third-party experiments in Mixpanel using these events, use [Option 2](#option-2--change-your-tracking-implementation) instead so that analysis keeps working.
</Warning>

## Option 2 — Change your tracking implementation

Change your third-party platform or in-house system to emit a different event name instead of the reserved `$experiment_started`.

This requires a code or configuration change on your side, and your new events won't be continuous with the `$experiment_started` events you've already sent — any saved report or dashboard built on the old event keeps referencing it. For most projects Option 1 is the simpler path.

Choose this option when either:

- You're on a **Free** plan, where the exposure event setting can't be changed.
- You want to keep your project's exposure event setting pointed at `$experiment_started` for some other reason.

## How to check your MEU usage

Go to **Organization Settings → Plan Details & Billing** to see your current MEU consumption against your allowance.

## FAQ

#### Does this delete or change my existing events?

No. Neither option modifies data already in your project. Your historical `$experiment_started` events remain intact and queryable in reports, cohorts, and exports.

#### Will my existing reports and dashboards keep working?

Reports that query `$experiment_started` as a regular event keep working under both options. Under Option 1, the [Experiment report](/docs/experiments) specifically will no longer pick up these events, because it reads whichever event your project has configured as the exposure event.

#### Can I switch back later?

Yes. Changing the exposure event setting back to `$experiment_started` resumes metering on those events from that point forward. Do this when you're ready to adopt Mixpanel Experiments.

#### What if I do want to use Mixpanel Experiments?

Leave the setting as-is and see [Experiments](/docs/experiments) to get started. If you run experiments through [Mixpanel Feature Flags](/docs/featureflags), exposure events are tracked automatically and you don't need to send them yourself.
