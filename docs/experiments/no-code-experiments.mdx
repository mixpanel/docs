No-code experiments let you build and launch A/B test variants on your website through a visual editor, with no code deploy per test. You open the page you want to test, click the element you want to change, edit it directly or describe the change to Mixpanel Agent, then launch.

<Warning>
  No-code experiments are in closed beta. Access is enabled per project. Contact your account team to request to join.
</Warning>

## Beta Scope

| | Supported in beta |
| --- | --- |
| Browser for authoring | Chrome only |
| Install method | Web snippet in your page's `<head>` |
| Site type | Best suited to static and marketing sites |

Complex single-page apps are better served by a code experiment. Mutations are applied to the rendered DOM, so the more dynamic the page, the less predictable the result. The visual editor re-applies mutations when elements re-render, but a heavily client-routed app will still behave less reliably than a static page.

Authoring is Chrome-only. The experiment itself runs for all of your end users in any browser, because the variant is delivered by the Mixpanel JavaScript SDK rather than by the extension.

## Visual vs Code Experiments

Mixpanel has two experiment types. You choose one at creation time.

| | Visual Experiment | Code Experiment |
| --- | --- | --- |
| Variants built in | The visual editor, on your live site | Your codebase |
| Code change per test | None | Yes |
| Who can run it | Anyone with the right permissions | Requires an engineer |
| Best for | Copy, styling, and layout changes | Backend logic, new components, anything data-driven |

Visual experiments run on [Mixpanel Feature Flags](/docs/featureflags), and the visual editor creates and configures the flag for you. You do not write any flag evaluation code, and you do not need an engineer to implement the flag. The one-time snippet install is the only code change the feature requires.

<Note>
  The experiment type can't be changed after the experiment is created. If you need to convert a test, create a new experiment.
</Note>

## Designing Variants

The editor opens your live site in a new tab with a toolbar for switching between variants and adding new ones. Select an element to edit it, or open Mixpanel Agent and describe the change you want.

### What You Can Change

| Change | Notes |
| --- | --- |
| Text | Replaces the element's text. Markup is not parsed. |
| Colors | Fill and gradient, through a color picker |
| Other CSS | Any CSS property, set as an inline style |
| CSS classes | Add or remove classes |
| Attributes | Including `src`, which is how you swap an image |
| Hide | Removes the element from the page for that variant |

Editing raw HTML is not currently supported. Moving, reordering, inserting, and duplicating elements are not available yet.

### Editing With Mixpanel Agent

Mixpanel Agent can apply several changes at once from a single description, such as restyling a set of buttons and swapping the copy in two sections. Agent proposes the changes, you approve them, and they land in the changes list like any other edit. Agent can only author visual changes from inside the editor; the dashboard chat hands off to the editor instead.

### Reviewing and Removing Changes

Every edit is recorded in a changes list in the editor. You can review each change and delete it individually, which is also how you undo a change: to unhide an element, delete the hide change. Clicking a change highlights the element it applies to. Multiple edits to the same element are condensed into a single entry.

## Targeting a URL

A variant applies to a page when the page's origin and path match the URL saved for that variant.

- Query strings and hash fragments are ignored, so `/cart?utm_source=email` matches `/cart`
- A trailing slash is ignored, so `/cart/` matches `/cart`
- Matching is case-sensitive, so `/Cart` does not match `/cart`
- Wildcards, prefixes, and regular expressions are not supported

To test several pages, create a separate experiment for each one.

### Overlapping Experiments

When you enter a URL that another draft or running visual experiment already targets, Mixpanel warns you and names the conflicting experiment. Overlapping visual experiments can interfere with each other and make results hard to attribute. The warning does not block you from saving or launching, so it's on you to decide whether the overlap is acceptable.

## Permissions

Launching a visual experiment requires the **Launch Visual Experiments** permission, which is separate from the ability to create or edit one. This lets you open variant design up to a wider group while keeping control over what reaches your users.

| Role | Can launch visual experiments |
| --- | --- |
| Owner | Yes |
| Admin | Yes |
| Analyst | Yes |
| Messenger | No |
| Consumer | No |
| Billing Admin | No |

Grant it to a custom role under Organization Settings, in the **Feature Flags and Experimentation** group of project permissions. Without it, a user can design variants and save them, but the launch action stays disabled.

## Limits and Known Issues

<Warning>
  Variants you create from inside the editor start at a 0% traffic split and are served to nobody until you set their split on the experiment page in Mixpanel. Check your variant splits before you launch.
</Warning>

- Editing variants on a running experiment changes what live users see immediately and can skew your results
- An experiment can't launch until at least one variant has an edit
- Don't edit the flag variant values by hand for a visual experiment; doing so breaks the editor
- Edits to elements inside dynamic feeds can be inherited by items that render later
- Visual changes are capped at 32KB per variant
- One editor session per user at a time. Opening the editor again ends the previous session
- Editor sessions expire after an hour
- Concurrent edits to the same variant overwrite each other, so coordinate before two people edit one experiment

### The Editor Reports the Extension Is Missing

Refresh the Mixpanel tab. Detection runs on page load. If it still fails, confirm you're on the latest extension and that older Mixpanel extensions are disabled.

### Changes Don't Appear on Your Site

Confirm the snippet loads the pinned beta build and passes both `flags: true` and `visual_experiments: true`. The editor reports an error when it detects that visual experiments are turned off in the SDK. Also check that the URL you're viewing matches the saved URL, keeping case sensitivity in mind.

## Launching and Reading Results

Launching and analysis work the same as any other experiment. Exposures are recorded when a user is assigned a variant, and results appear in the Experiments report. See [Monitor Your Experiment](/docs/experiments#monitor-your-experiment) and [Interpret Your Results](/docs/experiments#interpret-your-results).
