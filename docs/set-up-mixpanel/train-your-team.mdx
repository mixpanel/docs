## Overview

This phase gets your teammates using Mixpanel. You'll help them learn the basics, find answers on their own, and build a first report. Teammates need access first. [Choose how people get access](/docs/set-up-mixpanel/configure-your-account#choose-how-people-get-access)

<Info>
  Most people won't read a long guide before they try something. Let teammates build a report that answers a question they care about early, then point them to learning resources.
</Info>

**Done when:**

- Teammates know the basics
- They can find answers on their own
- They create their first report

## Get teammates up to speed

Help teammates go from having access to using Mixpanel on their own.

### Put reports on a board

A board gives teammates a place to start, so no one has to open Mixpanel to a blank page. Save a few reports that answer the questions you wrote down in Phase 1 to a board, and then share it with your teammates. [Boards](/docs/boards) · [Sharing](/docs/boards/sharing-and-permission)

### Help teammates build a report

Once teammates have seen a board, have each one build a report from a question they care about. Starting with their own question shows them what Mixpanel can do for their work. [Reports Overview](/docs/reports)

### Help teammates find answers

Once teammates are comfortable with the interface and can build a basic report, show them how to ask the Mixpanel Agent questions about your data. Teammates who've built reports can tell when an answer looks off. Have them open the report behind any answer and check it against the data before anyone acts on it. [Mixpanel Agent](/docs/mixpanel-agent)

### Help teammates learn the basics

Mixpanel Fundamentals is a beginner course that covers the core functionality of Mixpanel, so teammates can use Mixpanel with confidence. Some people like to start with the course, and others like to get hands-on with a new tool first. Either works, so share it with each teammate and let them decide when to use it. [Mixpanel Fundamentals](https://university.mixpanel.com/student/path/3411736-mixpanel-fundamentals)

## Set up other Mixpanel products

Some Mixpanel products need their own setup, even after your events are flowing. If your team is adding any of these, start here. Each one builds on the tracking you already have.

### Session Replay

Watch how people use your product, so you can see what a report can't show, like where someone hesitated before dropping off. Replay is turned on through your SDK, so bring in an engineer. [Session Replay](/docs/session-replay) · [Best Practices for Heatmaps & Session Replay](/guides/guides-by-use-case/empower-your-team/see-replays)

### Feature Flags

Release a feature to some of your users first, and turn it off without a new deploy if something goes wrong. Flags run through your SDK, so set them up with an engineer. [Feature Flags](/docs/featureflags) · [How to Safely Ship New Features with Flags](/guides/guides-by-use-case/engage-your-users/ship-features)

### Experiments

Test a change against what you have now, and find out whether it moved the metrics your team cares about. [Experiments](/docs/experiments) · [Drive Product Innovation with Mixpanel Experiments](/guides/guides-by-use-case/engage-your-users/drive-product-innovation)

### Metric Trees

Map how the metrics each team works on connect to the outcome that matters most, so everyone can see how their work adds up. [Metric Tree](/docs/metric_tree) · [Operationalizing Metric Trees](/guides/guides-by-use-case/empower-your-team/close-strategy-execution-gap)

### Data Pipelines

Keep a copy of your Mixpanel data flowing to your warehouse or cloud storage, so your data team can work with it alongside your other sources. [Data Pipelines Overview](/docs/data-pipelines)
