## 개요 [#overview]

Mixpanel 데이터는 [프로젝트](/ko/docs/orgs-and-projects/managing-projects) 단위로 저장되고 격리됩니다. 현재로서는 여러 프로젝트에 걸쳐 데이터를 조회할 수 없습니다. Mixpanel은 분석에 활용할 수 있는 몇 가지 데이터 범주를 지원합니다. 이벤트, 사용자 프로필, 그룹 프로필, 룩업 테이블이 그것입니다. 데이터 웨어하우스 용어로 표현하면 이벤트는 팩트 테이블에 해당하고, 사용자 프로필과 그룹 프로필, 룩업 테이블은 디멘전 테이블에 해당합니다.

  ![Data Model Overview](/images/Data_Model_Overview.png)

| 유형 | 설명 |
| --- | --- |
| **이벤트** | 이벤트는 제품 안에서 일어나는 행동을 나타냅니다. 이벤트는 그 행동을 설명하는 속성을 포함합니다. 또한 이벤트는 사용자 프로필, 그룹 프로필, 룩업 테이블과 조인하여 데이터를 보강할 수 있습니다. <br /><br /> [이벤트 속성 자세히 알아보기](/ko/docs/data-structure/events-and-properties) |
| **사용자 프로필** | 사용자 프로필은 사용자에 대한 상태를 담는 키/값 저장소입니다. 사용자 프로필은 `event.distinct_id = user_profile.distinct_id` 기준으로 이벤트와 조인됩니다. <br /><br /> [프로필 속성 자세히 알아보기](/ko/docs/data-structure/user-profiles) |
| **그룹 프로필** | 그룹 프로필은 그룹 구성원에 대한 상태를 담는 키/값 저장소입니다. 그룹 프로필은 지정한 _그룹 키_ 를 기준으로 이벤트와 조인됩니다. 예를 들어 `company_id`로 새 그룹 키를 만들면 이벤트는 `event.company_id = group_profile.company_id` 기준으로 조인됩니다. <br /><br /> [그룹 애널리틱스 자세히 알아보기](/ko/docs/data-structure/group-analytics) |
| **룩업 테이블** | 룩업 테이블은 특정 엔터티에 대한 상태를 담는 키/값 저장소입니다. 룩업 테이블은 지정한 조인 키를 기준으로 이벤트(및 다른 프로필)와 조인됩니다. 예를 들어 "Songs" 룩업 테이블을 만들고 조인 키를 `song_id`로 지정하면 이벤트는 `event.song_id = lookup_table.song_id` 기준으로 조인됩니다. <br /><br />[룩업 테이블 자세히 알아보기](/ko/docs/data-structure/lookup-tables) |

### 이벤트 속성과 사용자 프로필 속성의 차이 [#event-property-vs-user-profile-property]

이벤트 속성은 이벤트에 대한 세부 정보입니다.  이벤트 속성은 매우 중요합니다. 의미 있는 분석에 필요한 맥락을 이벤트에 부여하기 때문입니다. 또한 속성은 데이터를 세분화할 수 있게 해주어, 이벤트 기반 데이터에서 더 자세한 인사이트를 얻을 수 있게 합니다. 한번 트래킹된 이벤트와 그 속성은 변경할 수 없습니다.

프로필 속성은 특정 사용자에 대한 전반적인 정보를 알려줍니다. 다시 말해 프로필 속성은 지금 이 순간의 사용자 상태를 설명합니다. 사용자 프로필 속성은 이름처럼 고정된 값일 수도 있고, 마지막 로그인 날짜나 사용자가 재생한 곡 수처럼 자주 바뀌는 값일 수도 있습니다.

예를 들어 이벤트 속성이나 슈퍼 속성은 사용자가 특정 행동을 했을 당시에 유료 계정이었는지 무료 계정이었는지를 시점별로 알려주지만, 프로필 속성은 현재 유료인지 무료인지만 보여줍니다.

## 예시 [#example]

음악 스트리밍 제품을 담당하고 있고 다음과 같은 질문에 답하고 싶다고 가정해 보겠습니다.

- 이번 주에 가장 인기 있는 곡과 아티스트는 무엇인가?
- 사용자별 주간 재생 곡 수의 분포는 어떻게 되는가?
- 무료 계정에서 프리미엄 계정으로의 전환율을 높이기 위한 A/B 테스트에서 어떤 실험이 더 좋은 성과를 냈는가?

사용자 기준과 계정 기준 모두로 순 사용자 수를 분석하고 싶어 `account_id`로 그룹 키를 만듭니다. 또한 재생된 곡에 대한 정보로 이벤트를 보강하고 싶어 "Songs" 룩업 테이블을 만들고 조인 키를 `song_id`로 지정합니다. 이때 데이터 모델은 다음과 같은 형태가 됩니다.

Mixpanel 데이터는 **이벤트** 와 **프로필** 로 구성되며, 각각은 다시 **속성** 으로 이루어집니다.  이벤트는 시계열 데이터베이스에 저장되는 데이터 포인트이고, 프로필은 키-값 저장소입니다.

## 이벤트의 구조 [#anatomy-of-an-event]

아래 이벤트는 사용자 `john.doe@gmail.com`이 2020년 9월 29일 화요일 GMT 오후 8시 42분 11초에 IP 203.0.113.9인 기기에서 song\_id가 `0wwPcA6wtMf6HUMpIRdeP7`인 곡을 재생했다는 사실을 나타냅니다.

```json
{
  // 이벤트 이름
  "event": "Played Song", 

   // 이벤트에 대한 메타데이터를 담는 속성 딕셔너리
  "properties": { 

    // 프로젝트에 연결된 Mixpanel 토큰입니다. Mixpanel 앱의 프로젝트 설정
    // 대화상자에서 토큰을 확인할 수 있습니다. 유효한 토큰이 없는 이벤트는
    // 무시됩니다.
    "token": "6972694d809c7390676a138834f8c890",

    // 이벤트가 발생한 시각입니다. 값을 지정하는 경우 Unix 타임스탬프
    // (UTC epoch 이후 밀리초)여야 합니다. 요청에 이 속성이 없으면
    // Mixpanel은 이벤트가 서버에 도착한 시각을 사용합니다. 모바일 SDK를 사용하는 경우
    // 자동으로 설정됩니다.
    "time": 1601412131000,

    // 이벤트에 연결된 IP 주소 문자열입니다(예: "127.0.0.1"). 이벤트에
    // 위치 정보를 추가하는 데 사용되며, 백엔드에서 요청을 보내는 경우에만
    // 필요합니다. IP가 없고 URL 파라미터로 ip=1도 전달하지 않으면
    // Mixpanel은 요청의 IP 주소를 무시합니다.
    "ip": "203.0.113.9",

    // 이벤트의 고유 식별자입니다. Mixpanel은 재시도나 네트워크 오류로 인한
    // 이벤트 중복을 제거하는 데 이 값을 사용합니다. (event, time, distinct_id, $insert_id)가
    // 모두 같은 이벤트는 중복으로 간주됩니다. 
    // $insert_id로는 UUID 생성을 권장합니다. Mixpanel SDK는 이를 자동으로 처리합니다.
    "$insert_id": "5d958f87-542d-4c10-9422-0ed75893dc81",

    // distinct_id 값은 문자열로 처리되며, 이벤트와 연결된 사용자를 
    // 고유하게 식별하는 데 사용됩니다. 이벤트에 distinct_id 속성을 함께 보내면
    // 퍼널에서 특정 사용자를 추적하고 리텐션 분석에서 순 사용자를 
    // 구분할 수 있습니다. 같은 사용자가 발생시킨 이벤트에는 항상 동일한
    // distinct_id를 보내야 합니다.
    "distinct_id": "john.doe@gmail.com",

    // 이벤트에 대한 메타데이터로 트래킹하고 싶은 임의의 속성을
    // 자유롭게 지정할 수도 있습니다
    "app_version": "1.1.34.694.gac68a2b3",
    "song_id": "0wwPcA6wtMf6HUMpIRdeP7"
}
```

## 사용자 프로필, 그룹 프로필, 룩업 테이블 [#user-profiles-group-profiles-lookup-tables]

세 가지 모두 엔터티에 대한 추가 메타데이터로 이벤트 데이터를 보강하는 키/값 저장소입니다. 차이는 조인 키를 직접 지정할 수 있는지, 그리고 이벤트가 조인 키 기준으로 복사되어 인덱싱되는지에 있습니다.

[**사용자 프로필**](/ko/docs/data-structure/user-profiles)은 이벤트의 기본 인덱스인 `distinct_id`를 통해 이벤트와 조인됩니다.

[**그룹 프로필**](/ko/docs/data-structure/group-analytics)은 그룹 키로 지정한 이벤트 속성을 통해 이벤트와 조인됩니다. 새 그룹 키를 만들면 해당 속성을 기준으로 이벤트에 인덱스가 추가됩니다. 이를 통해 `distinct_id` 대신 그 속성을 기준으로 퍼널이나 리텐션 분석을 수행할 수 있습니다.

[**룩업 테이블**](/ko/docs/data-structure/lookup-tables)은 직접 지정한 조인 키를 통해 이벤트 및 사용자 프로필과 조인됩니다. 그룹 프로필과 달리 이벤트는 조인 키 기준으로 인덱싱되지 _않습니다_. 룩업 테이블 속성으로 필터링이나 브레이크다운 등은 할 수 있지만, 조인 키를 순 사용자 기준으로 사용하는 퍼널 분석 같은 작업은 할 수 없습니다. 참고: 현재 그룹 프로필 속성은 룩업 테이블 키로 사용할 수 없습니다.

| 프로필 유형 | 조인 키 지정 가능 | 조인 키로 순 사용자 분석 가능 | 다른 프로필에서 참조 가능 |
| --- | --- | --- | --- |
| 사용자 프로필 | ❌ | ✅ | ❌ |
| 그룹 프로필 | ✅ | ✅ | ❌ |
| 룩업 테이블 | ✅ | ❌ | ✅ |
