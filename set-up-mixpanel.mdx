How fast you get started with Mixpanel is mostly up to you. Smaller teams can usually move quickly, while larger teams may take longer because more people have to weigh in. What you control most is how long work sits waiting for a decision or for someone to pick it up.

Don't wait for one stage to be perfect before you start the next. You're moving well when each stage has a named owner and a next step on the calendar. If a stage stalls, or you're waiting on a decision, ask for help early.

## **What you'll need to set up**

Someone to decide what to track, someone who can add code, and access to your [Mixpanel organization](/docs/orgs-and-projects/organizations). A team of one? You'll do both.

## **Choose how you want to set up**

You can set Mixpanel up with an AI coding agent or by following the steps yourself. Both get you to the same place with clean data flowing into Mixpanel, so pick the one that fits how your team works.

### **Set up with AI** 

Your agent reads your codebase, suggests events, and adds the SDK. You review every change. Best if your team already uses a coding agent like Claude Code or Cursor. No codebase access? The tool can write a spec for a developer to follow instead.

### **Set up yourself**

Follow the steps to install the SDK, send your first events, and check them. Best if you'd rather write the code yourself, or your company’s policies keep AI tools away from your code.

## What speeds you up

- Start with a few [events](/docs/quickstart/capture-events). You can add more once data is flowing.
- Send test events to a [development project](/docs/tracking-best-practices/developer-environments) first.
- Set up [identify](/docs/quickstart/identify-users) when you first send data. It's hard to fix later.
- Ask the [Mixpanel Agent](/docs/mixpanel-agent) to help you get set up.
